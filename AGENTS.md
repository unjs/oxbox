oxbox is a tiny redistribution of OXC (transformer and parser) packaged as a universal package (via wasm) runnable in Node.js and Browsers

- Keep implementation minimal, target low bundle size, speed and portability
- Only use comments where necessary and not obvious in code

## Structure

- `src/napi.ts`: minimal N-API + WASI + wasi-threads host for napi-rs `wasm32-wasip1-threads` builds (only imports oxc uses)
- `src/worker_threads.ts`: subset of `node:worker_threads` used by `napi.ts` (`Worker`, `parentPort`, `workerData`) with a Web Worker fallback (module workers, `workerData` sent as first message)
- `src/index.ts`: public API, same as `oxc-transform` + `oxc-parser` (`parse`, `parseSync`); lazily loads the wasm on first call (sync APIs via `node:zlib`, async APIs and `init()` via `DecompressionStream` + async compile; browsers must `await init()` before sync APIs; with threads `init()` also prewarms the async work pool with one small job per worker); without threads (`canUseThreads()`: no `SharedArrayBuffer`/cross-origin isolation or workers) the memory import is patched to non-shared and async APIs run their sync variants
- `src/_vendor/wasm.ts`: committed, generated by `pnpm vendor`: `oxcVersion` + wasm embedded as deflate-raw (zopfli, web `DecompressionStream` compatible) + base93 string (13 bits per 2 printable ASCII chars except `"` and `\`) + `wasm()` (sync, `node:zlib`) / `wasmAsync()` (`DecompressionStream`) decoders (lint/fmt ignored)
- `rust/`: `oxbox` cdylib linking oxc's `napi/transform` + `napi/parser` crates from `vendor/oxc` (path deps)
- `rust/.cargo/config.toml`: replaces `napi build` (target + `EMNAPI_LINK_DIR` from the `emnapi` devDependency) and enables `simd128`; link args come from `napi-build`
- `scripts/vendor.ts`: clones oxc at `crates_v<version>` into `vendor/oxc` (gitignored), builds `rust/` with remapped paths (reproducible), writes `src/_vendor/wasm.ts`
- `scripts/zopfli/`: host Rust tool (`zopfli` crate) used by `scripts/vendor.ts` to deflate the wasm (stdin -> stdout)
- `build.config.ts`: obuild bundle (wasm is inlined via the `_vendor/wasm.ts` import); `napi.ts` + `worker_threads.ts` go to their own chunk (`_chunks/napi.mjs`) since workers import the spawning module (`import.meta.url`)
- `test/`: compares output against native `oxc-transform` / `oxc-parser`
- `bench/`: mitata benchmarks (`pnpm bench [filter]`): startup + `transform(Sync)` / `parse(Sync)` of oxbox vs oxc wasm (`@oxc-*/binding-wasm32-wasi`) vs oxc napi on pinned inputs of oxc's own benchmarks, all free of diagnostics (fetched into `bench/.fixtures`, gitignored); console output uses mitata `summary()`; unfiltered runs write `bench/results.json` and render it via `bench/report.ts` (`pnpm bench:report`, no re-run needed) to `bench/results.svg` (README chart, white background, env footer); `bench/results.*` are generated and fmt ignored; `bench/size.ts` (`pnpm bench:size`, builds first) measures install size (package files + installed deps, raw and gzip) of oxbox `dist` vs oxc wasm vs oxc napi and renders `bench/size.svg` (README chart) with one stacked bar per impl (transform + parser + shared deps segments)
- `playground/`: browser playground (pnpm workspace package; Vite + React + Tailwind, `rangi` highlighting), served cross-origin isolated (COOP/COEP) for `SharedArrayBuffer`; run with `pnpm dev`

## Notes

- No top-level `node:` imports; access Node.js APIs lazily via `getBuiltin()` (`process.getBuiltinModule`) and prefer web APIs
- Keep `oxc-transform`, `oxc-parser` and their `@oxc-*/binding-wasm32-wasi` (bench) devDependencies on the same version (the oxc tag is derived from them); run `pnpm vendor` after bumping and commit `src/_vendor/wasm.ts`
- `pnpm vendor` needs Rust with the `wasm32-wasip1-threads` target (`rustup target add wasm32-wasip1-threads`); tests/CI use the committed wasm
- When the wasm gains new napi imports, implement them in `src/napi.ts`
- Run `pnpm test` (lint + typecheck + vitest) and `pnpm fmt` before finishing
